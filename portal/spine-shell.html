Case Spine

A single conformed row per case, joined to site, scanner, model version and stratum — so that questions currently spanning seven disconnected systems become one query. Every lens below is a projection over the same table.

Synthetic data · no Heartflow records used
The spine is six columns: case_id · site_id · scanner_id · model_version · timestamp · stratum. Facts stay in the systems that own them; the spine carries only keys. That is what makes this a two-week build rather than a two-year warehouse.

Projection 07 · the silent failure

Detector transition

Photon-counting CT measures roughly a third less total plaque volume than energy-integrating detectors, and EID-derived thresholds do not transfer. When a site swaps scanners its numbers move for reasons unrelated to its patients — with no error raised anywhere.

Compliance posture

Why this passes review

  • Production & quality-system software, not device software. Validated under FDA Computer Software Assurance (final Sept 2025, reissued 3 Feb 2026 to align with QMSR) — risk-based, unscripted testing, automated test results as evidence. It observes; it never routes a case. The moment a lens decides which cases skip human review, it crosses into device software and a different regime.
  • PHI-free analytics layer. Pseudonymous case surrogates, covariate summaries and edit semantics only. No pixel data, no DICOM tags, no accession numbers, no raw mesh geometry. Re-identification map is a separate access-controlled store that only Post-Market Quality can traverse, because complaint investigation legally requires it.
  • No analyst identity in the spine. Not pseudonymised — absent. Aggregation is by case stratum, so the system is structurally incapable of individual performance monitoring. That is what keeps Operations on side.
  • Runs in their account, their VPC. Existing HITRUST, ISO 27001 and SOC 2 Type 2 scope is unchanged. No vendor qualification, no new DPA.
  • Deploys into existing EKS node groups using prefix delegation rather than requesting new subnets — their public GitHub org carries a fork of AWS's subnet IP-utilisation monitor, which suggests address exhaustion is a live constraint.
